## 1. 目標、使用者與情境

以中等開發難度建立可部署至 GitHub Pages 的演唱會模擬搶票 Web App，完成「首頁 → 開賣倒數 → 排隊 → 選位 → 結帳 → 結果」六階段。重點為可實際遊玩、規則一致、具限時壓力，以及桌機與手機都能完成操作。

| 使用者 | 使用情境 | 核心需求 |
| --- | --- | --- |
| 演唱會粉絲／有搶票經驗者 | 重玩不同排隊順位與座位庫存 | 動態售出、跨區選位、限時操作 |
| 搶票新手 | 練習選位與確認訂單 | 階段提示、清楚狀態、可修正操作 |
| 小遊戲玩家 | 挑戰最快結帳 | 耗時、結果與分張數最佳紀錄 |
| 課堂展示者 | 展示完整互動與技術成果 | 短排隊、可重新挑戰、靜態部署 |

不提供帳號、真實付款、多人共享庫存、真實購票服務或全球排名。

### 4.1 庫存不足的明確定義

計算「已選數＋未選可售數」。若小於目標兩張但至少有一席可完成單張購票，顯示改買一張的提示，不自動修改。若已有一席被保留，即使其他席位全售出也不立即失敗；玩家可改為一張並結帳。玩家不調整時，倒數繼續，最後可能逾時。

### 4.2 成績與紀錄

- 總流程時間：按開始搶票至本局結算，包含 10 秒倒數、排隊及選位結帳。
- 選位結帳時間：進入選位至本局結算，包含返回操作與背景分頁時間。
- 成功最佳：依最終實際購票 1 或 2 張分組，使用選位結帳耗時比較；相同耗時建議保留原紀錄。
- 每局紀錄：runId、結果、失敗原因（如有）、目標張數、成功實購張數、兩種耗時、完成日期與資料版本。
- 失敗局的實購張數為 0，不參與最佳比較。重整／關閉中斷不寫入紀錄。
- 最佳紀錄獨立保存，不因最近 10 局淘汰而消失。顯示到小數一位，內部保留較精確耗時。
- 本機紀錄不是防作弊系統，也不跨裝置同步。

## 6. 排隊與計時建議

建議以等機率抽整數順位，並線性插值：順位 1 對應 35%、順位 5,000 對應 80%，中間順位依相對位置遞增。初始售出席數取整後不得超過總可售席數減二；具體取整建議向下取整。上述抽樣及取整屬實作建議，不改變已確認的比例範圍與至少兩席保障。

畫面順位逐步下降，但初始庫存以入場前已抽定的起始順位決定。等待秒數不宣稱與順位成比例。

遊戲期限以時間戳計算，不能只靠每秒減一。選位、驗證、返回、提交等事件都先檢查期限並對齊售出排程。背景分頁不暫停；恢復後補算已到期事件，詳見 GAME_FLOW。

## 7. 技術、隱私與範圍

依使用者最終交付要求，使用單一 index.html，內嵌 HTML、CSS、一般 JavaScript、SVG 與 application/json 座位資料；不依賴 ES Modules 匯入、外部圖片、字型或 CDN。無後端、付費 API、登入或機密金鑰，支援直接開檔，亦適合 GitHub Pages 靜態部署。

localStorage 只持久保存已完成紀錄；不保存可恢復的進行中局。中斷提示可用 sessionStorage 的非恢復性標記；即使不可用，也能從首頁重新開始。

桌機與手機可完整通關屬 MVP。進階手機手勢、額外視覺優化、音效、多難度、統計與票券下載列第二版。

## 8. 風險與驗收

| 風險 | 對策 | 驗收案例 |
| --- | --- | --- |
| 時間漂移／背景節流 | 時間戳期限、恢復時對齊事件 | 切到其他分頁超過 120 秒後，回來立即失敗 |
| 到期瞬間提交 | 當下時間大於等於期限即失敗 | 期限前有效提交成功；期限到或之後一律失敗 |
| 連點／重複選位 | 唯一 seatId、狀態單一來源、結算鎖 | 快速重複點擊不產生重複席或紀錄 |
| 售出與選取競態 | 先補售出事件，再處理點選；保留席排除 | 同一席不會同時被保留又售出 |
| 跨區遺失選位 | 已選 IDs 屬本局，不屬單區元件 | 選兩個不同分區後摘要、金額、圖示一致 |
| 張數下降誤釋放 | 指定保留席後才提交變更 | 取消選擇對話框時仍保留兩席與原張數 |
| 返回未釋放／重設時間 | 狀態轉移統一處理 | 確認返回後兩席皆釋放、目標不變、期限不變 |
| 不足兩席／完售 | 依已選與可售數分流 | 保留一席時可改一張；無保留且無票立即失敗 |
| 驗證錯誤 | 可重試、換碼不延時 | 大小寫皆可；換碼後舊碼無效；空白提示 |
| 重整／重開 | 不持久保存局進度 | 各進行階段重整皆回首頁，不新增勝敗紀錄 |
| 資料毀損／超額 | 讀取驗證、例外降級 | localStorage 禁用或格式錯誤仍可通關 |
| 最佳被歷史淘汰 | 最佳與最近紀錄分開 | 超過 10 局後仍保留更早最快紀錄 |
| 手機誤觸／圖太密 | 單區放大、拖曳、較大操作目標 | 360px 寬可完成跨區購買，不靠全頁橫向捲動 |
| 缺格／錯價／重複座號 | 靜態資料核對與一致性檢查 | 每席 ID 唯一、價位有效、空缺不可選、標記可追溯 |
| 舊局回呼污染新局 | runId 與終局清理 | 連續重玩不加速計時、不出現舊票券 |
| 減少動畫需求 | 尊重 prefers-reduced-motion | 停用粒子／閃動後所有提示與流程仍可用 |

核心成功驗收必須包含：一張票、同區兩張、跨區兩張、不同價位兩張、返回重選、驗證重試、兩種終局失敗與重新挑戰。
