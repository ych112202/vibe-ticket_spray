## 2. 第二版擴充

- 新手／標準／困難，依難度分開保存最佳紀錄。
- 遊戲音效、靜音控制，必要時再考慮背景音樂。
- 勝敗統計、成功率與更多紀錄篩選。
- PNG 電子票券下載或專用列印／PDF 版面。
- 更完整的手機手勢與動畫優化。
- 依更多可確認資料修正模擬座號與分區。

跨裝置同步、真實付款、會員及多人共享庫存不在目前計畫內，若日後需求改變需重新評估架構。

## 4. 技術方案

採原生 HTML／CSS／JavaScript，依最終要求全部內嵌於單一 index.html，不使用 ES Modules 匯入或外部資源，無需框架、後端、付費 API 或機密金鑰。自繪 SVG 分為分區總覽與局部座位，完整 6,218 席資料亦內嵌；不直接展示或打包原始參考圖片。

狀態集中管理、畫面僅渲染狀態；選位、售出、返回、結算從同一套狀態入口修改，避免各畫面各自維護一份座位與時間。計時器只負責觸發更新，真實剩餘時間從期限計算。

localStorage 使用具版本的專案前綴鍵，例如 concertQuest.records.v1 與 concertQuest.bests.v1。讀取時檢查格式與內容，失敗時降級；進行中的選位及訂單不持久化。sessionStorage 中斷標記僅用於提示，不提供恢復功能。

### 實際交付結構

```text
CONCERT-QUEST/
├─ index.html                  # 唯一執行檔：HTML、CSS、JavaScript、SVG、座位資料
├─ README.md
└─ docs/                      # 規格、座位附件、測試紀錄與靜態審閱圖；非執行依賴
```

單檔內以 TicketGame 類別集中處理規則，畫面、SVG、時鐘及儲存函式按責任區分。單獨複製 index.html 即可遊玩；不需要 src、assets、node_modules 或 docs。

## 5. 座位資料製作方法

依使用者最新決定，[SEAT_INVENTORY](SEAT_INVENTORY.md) 的範圍已通過，另按要求完成 [SEAT_ROWS](SEAT_ROWS.md) 的 25 區模擬缺格。CQ-SEATS-1 共 38 入口、463 排、6,218 席，新增精確缺格非官方核實。正式資料轉換時直接使用有效座號集合，不把缺格補滿或當成售出；畫面坐標與尚未明列方向留待 SVG 布局。

1. 建立分區清冊，對照區域圖與 overall，記錄重複名稱、單雙號、樓層及衝突。
2. 放大逐區核對，VIP 使用獨立座號圖輔助，標記每排有效座號與缺格。
3. 可辨識內容註記 reference-legible；模擬補足內容註記 simulated，保留原因。
4. 設計總覽輪廓與各區局部格線，不把全場數千席同時縮在手機上點選。
5. 將 PROJECT_SPEC 已確認的票價表對應到各 sectionId，特別檢查藍1A-1、藍5A-3 例外及模擬無障礙席優先規則；不以 SVG 像素距離自動決定金額。
6. 資料驗證：唯一 ID、分區參照、票價、重複座標、模擬標記、缺格及舞台範圍。

## 6. 測試計畫

規則與計時涉及終局和競態，適合加入可控制時間及隨機來源的自動測試；低影響文字與純樣式調整採人工檢查即可，不寫只重述實作的測試。

| 類型 | 重點案例 |
| --- | --- |
| 流程 | 一張成功、同區兩張、跨區不同價位兩張、錯碼後成功、重新挑戰 |
| 庫存 | 起始至少兩席、順位售出比例遞增、已選不售出、單張補救、全場完售 |
| 計時 | 10 秒、5～10 秒、共用 120 秒；售出於 4、8……56 及 60、62……118 秒觸發，60 秒一次、120 秒不售出；150 席售出 2 席、30 席售出 1 席；期限前後提交 |
| 背景 | 留在背景跨過多次售出與期限，恢復後狀態及原因一致 |
| 訂單 | 兩改一指定保留、取消對話框、返回全釋放、不重設期限、金額一致 |
| 紀錄 | 最近 10 局、最佳不被淘汰、分張數、同局不重複、重整中斷不計入 |
| 儲存 | 禁用、格式毀損、版本不符時不阻擋遊戲 |
| 資料 | 席位唯一、缺格不可選、來源可追溯、模擬分區與票券標示；藍1A-1／藍5A-3 為 3,680，其餘藍 A 區 4,280；模擬無障礙席優先固定 3,680 |
| 裝置 | 360／390／768px 與桌機；目標桌機瀏覽器及至少一個實際手機瀏覽器，清單開發時確認 |
| 操作 | 鍵盤焦點、觸控縮放拖曳、快速連點、對話框逾時、減少動畫 |
| 部署 | 專案子路徑、大小寫與資源載入、重新整理、無控制台錯誤、部署網址通關 |

保留簡短驗收紀錄，包含環境、情境、預期／實際與結果；失敗項修正後只重跑受影響規則及必要迴歸。正式測試結果待開發完成後填寫，目前不宣稱通過遊戲測試。
