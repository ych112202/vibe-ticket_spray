## 環境與方法

- Windows，Chrome 155.0.8059.40，透過 Playwright 啟動無頭瀏覽器。
- 直接使用本機 file 開啟單一 HTML，未啟動後端、不需要網路服務或額外資源。
- 另外將 index.html 複製到沒有其他檔案的獨立資料夾，確認可載入首頁並開始倒數，只有 HTML 本身的一次檔案請求。
- 桌機 1440×1050；手機模擬 390×844、360×800，包含觸控事件與拖曳檢查。手機不是實體裝置測試。
- 核心規則以可控制時間與隨機來源的測試核對，瀏覽器計時以可控時鐘驗證，避免實際等待多輪 120 秒。
- 畫面另檢查首頁、分區總覽、單區選位、結帳、成功票券與失敗結果；檢查時尊重減少動畫設定。

## 瀏覽器互動與儲存：通過

- 六階段正常切換，顯示 38 個總覽入口。
- 逐一開啟 38 個單區 SVG，DOM 有效席總和為 6,218，與內嵌資料一致。
- 實際以畫面操作跨區選兩席、兩改一取消／確認、返回結帳取消／釋放。
- 驗證錯誤提示、換碼與有效提交正常，一張票產生一張票券。
- 不同價位跨區雙張訂單（6,280＋3,680＝9,960 元）產生兩張票券，雙張最佳紀錄正確分組。

- 進行中重整回首頁，顯示中斷提示，不新增勝敗紀錄。
- 390px 與 360px 無全頁水平溢出，手機底部確認按鈕可正常操作。
- 縮放、真實觸控點選正常；拖曳座位圖不誤選。
- 結帳與返回確認對話框期間倒數持續；逾時自動關閉對話框並顯示失敗。
- localStorage 格式毀損或存取被拒絕時顯示提示，不阻擋遊戲。
